# infocyph/nginx

Hardened Nginx edge image for [LocalDevStack](https://github.com/infocyph/LocalDevStack). It provides local HTTP-to-HTTPS routing, TLS termination, generated project vhosts, LocalDevStack convenience routes, WebSocket/SSE support, invalid-vhost quarantine/recovery, and an optional streaming route to the local LLM service.

The image intentionally remains an edge proxy. Certificate issuance, project/service lifecycle, Docker orchestration, databases, and LLM model management stay outside this repository.

## Images

The same multi-architecture image is published to:

```text
docker.io/infocyph/nginx
ghcr.io/infocyph/nginx
```

Supported platforms:

```text
linux/amd64
linux/arm64
```

Release tags are immutable. `latest` is rebuilt weekly and on manual refresh from the latest stable docker-nginx release source against the current rolling dependencies, including `nginx:alpine`, Scriptomatic `main`, and the latest stable Toolset release.

## Ports

The image exposes the standard HTTP/TLS edge ports plus the provider-neutral native LLM proxy listener:

```text
80
443
11434
```

Port `11434` is an Nginx listener that proxies to the selected provider through the
common Docker DNS identity `llm:11434`; it is not the provider container itself.
LocalDevStack publishes this listener loopback-only as `127.0.0.1:11434:11434`.
The portable contract on this common route is the OpenAI-compatible `/v1` API.

## Required LocalDevStack mounts

LocalDevStack owns the certificates and generated vhosts. The runtime expects the corresponding paths to be mounted/provided:

```text
/etc/nginx/conf.d              generated project/service vhosts
/etc/mkcert/lds-server.pem     local TLS certificate
/etc/mkcert/lds-server-key.pem local TLS private key
/etc/share/rootCA/rootCA.pem   local trusted root CA
```

`/etc/nginx/locals.conf` remains image-managed and intentionally lives outside `/etc/nginx/conf.d`, because LocalDevStack mounts the latter.

A newly-created vhost volume is not seeded with the official upstream Nginx `default.conf`; the file is removed during the image build. Existing LocalDevStack volumes created by older images may still need one-time cleanup.

## Convenience routes

Reserved routes are generated by the image and cannot be overridden by `LOCALHOST_ROUTES`:

| Host | Upstream |
| --- | --- |
| `admin.localhost` | `server-tools:9911` |
| `webmail.localhost` | `mailpit:8025` |
| `db.localhost` | `cloud-beaver:8978` |
| `ri.localhost` | `redis-insight:5540` |
| `me.localhost` | `mongo-express:8081` |
| `kibana.localhost` | `kibana:5601` |
| `llm.localhost` | selected provider via `llm:11434` |
| `llm-ollama.localhost` | `llm-ollama:11434` |
| `llm-fastflow.localhost` | `llm-fastflow:11434` |

Known HTTP hosts redirect to HTTPS. Unknown HTTP/TLS hosts are rejected instead of falling through to an arbitrary route.

### Additional local routes

`LOCALHOST_ROUTES` adds Docker-service routes using a comma-separated `host=service:port` format:

```text
LOCALHOST_ROUTES=app.localhost=my-app:8080,metrics.localhost=metrics_ui:9090
```

Rules:

- hosts must be valid DNS labels inside `.localhost`;
- ports must be `1..65535`;
- Docker service names may use letters, digits, dots, hyphens, and underscores as supported by the route parser;
- reserved hosts cannot be replaced;
- if the same custom host appears more than once, the first valid entry wins;
- route values are treated as data and are never evaluated as shell code.

The convenience-route body limit defaults to `10G` for LocalDevStack compatibility and can be changed with a validated value such as:

```text
LOCALHOST_CLIENT_MAX_BODY_SIZE=512M
```

Supported suffixes are standard Nginx size units accepted by the renderer (`K`, `M`, `G`, case-insensitive); invalid values fail configuration rendering instead of being interpolated into Nginx config.

## Local LLM endpoints

LocalDevStack exposes three reserved LLM identities:

```text
llm.localhost          -> selected provider through llm:11434
llm-ollama.localhost   -> llm-ollama:11434
llm-fastflow.localhost -> llm-fastflow:11434
```

The common identity is the application-facing contract. Its portable API is:

```text
https://llm.localhost/v1/...
http://127.0.0.1:11434/v1/...
```

Provider-specific identities remain available for diagnostics and native operations.
For example, Ollama-native endpoints stay on:

```text
https://llm-ollama.localhost/api/tags
https://llm-ollama.localhost/api/chat
```

FastFlow's provider-specific route exposes its OpenAI-compatible API:

```text
https://llm-fastflow.localhost/v1/models
https://llm-fastflow.localhost/v1/chat/completions
```

LocalDevStack normalizes whichever provider is selected onto the internal LLM ABI port
`11434`. Ollama already listens there; FastFlow is configured with
`FLM_SERVE_PORT=11434` when used inside LocalDevStack. The selected provider also owns
the Docker-network alias `llm`.

All LLM routes use HTTP/1.1 streaming with proxy/request buffering disabled, gzip
disabled, Docker DNS re-resolution, and a dedicated long-running request budget.
`LLM_PROXY_TIMEOUT_SECONDS` defaults to `1800` (30 minutes) and controls only the LLM
route proxy send/read timeouts. Nginx starts normally when one or both provider-specific
services are absent; Docker DNS is resolved lazily at request time.

No wildcard CORS policy is added here. Browser-origin policy belongs to the selected LLM
runtime contract.

## Generated Nginx includes

The image provides reusable generated includes under `/etc/nginx`:

```text
fastcgi_params
fastcgi_streaming
proxy_params
proxy_fixedip_headers
proxy_timeouts
proxy_buffers
proxy_websocket
proxy_streaming
proxy_csp_relax
proxy_h2_sanitize
```

Important contracts:

- `proxy_params` carries canonical forwarding/request-ID headers but deliberately does not globally choose an upstream `Host` value;
- convenience/LLM routes explicitly preserve their requested local `Host`;
- vendor-specific client-IP headers are not trusted or forwarded by default;
- WebSocket upgrade headers are applied without forcing ordinary HTTP requests to `Connection: close`;
- streaming remains explicit rather than disabling buffering globally;
- CSP relaxation remains opt-in and local-development-only.

## Invalid-vhost quarantine

Generated project vhosts can temporarily be invalid while another tool is writing or repairing them. At startup, the entrypoint can quarantine identifiable bad files under `/etc/nginx/conf.d` so one broken project does not prevent the whole local edge from starting.

Runtime controls:

| Variable | Default | Meaning |
| --- | ---: | --- |
| `AUTO_DISABLE_INVALID_CONFS` | `1` | Quarantine identifiable invalid `conf.d/*.conf` files during validation. |
| `MAX_DISABLE_ATTEMPTS` | `100` | Bounded maximum invalid-file quarantine attempts per validation pass. |
| `AUTO_RESTORE_DISABLED_CONFS` | `1` | Watch quarantined/replacement configs for meaningful changes. |
| `AUTO_RESTORE_INTERVAL_SECONDS` | `5` | Change-detection interval while Nginx is running. |

Recovery is change-aware: unchanged broken files are not repeatedly restored/quarantined. A repaired quarantined file or a valid active replacement can be validated and reloaded. Unrelated/global Nginx errors remain fatal, and a read-only config mount fails clearly when quarantine would require mutation.

The long-lived watcher only starts when the container is actually launching foreground Nginx; diagnostic commands do not get an unnecessary background management loop.

## Healthcheck

The Docker healthcheck runs `nginx-healthcheck`. It verifies:

1. the Nginx master process is alive; and
2. the current Nginx configuration passes `nginx -t`.

It is deliberately independent of application services, databases, mail, or an LLM provider, so optional/downstream service availability does not make the edge container unhealthy.

## TLS policy

The local edge supports TLS 1.2 and TLS 1.3 using LocalDevStack-managed certificates. HSTS is not enabled by default, certificates are not generated inside this image, and HTTP/3/QUIC is outside the scope of this image.

## Development and verification

Static/contract checks:

```bash
bash tests/static.sh
bash tests/dependency-contract.sh
bash tests/release-contract.sh
```

Build a local candidate and run the same final image gate used by CI:

```bash
docker build --pull -t infocyph/nginx:ci .
bash tests/release-gate.sh infocyph/nginx:ci
```

The release gate uses lightweight mock upstreams for routing, WebSocket/streaming, LLM, Docker-DNS late-start recovery, invalid-vhost recovery, health, and signal behavior. It does not download an LLM model.

## Release pipeline

Publishing is triggered by a stable GitHub release, the weekly refresh, or manual dispatch.

For a release event, the workflow builds from the exact released source and publishes the immutable release tag plus `latest`. Scheduled/manual refreshes resolve the latest stable published docker-nginx source and update only `latest`; draft/prerelease sources are rejected.

Before publishing, fresh amd64 and arm64 candidates are gated. The multi-platform image is then published with BuildKit SBOM/provenance and GitHub/Sigstore attestations. Docker Hub and GHCR are required to resolve to the same resulting manifest digest, and the pushed amd64 artifact is smoke-tested by digest.
